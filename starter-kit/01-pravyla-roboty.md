# Правила роботи

Як ми зробили Rooftop Hide & Seek від однієї фрази до гри з онлайном, вежами й дронами.

## 1. Ідея → бриф

1. Ти пишеш ідею своїми словами, хоч одним реченням.
2. Claude ставить одне коло питань (до 8): режим, відчуття, вигляд, складність, ціль. Відповідай як хочеш, можна просто «на твій вибір».
3. Референси (картинки, які подобаються) кидай прямо в чат або в папку `references/`. Вони лишаються тільки на ноутбуці й ніколи не потрапляють у гру чи на GitHub.
4. Claude пише **бриф** — одну сторінку про гру (`design/game-brief.md`). Твої слова там зберігаються дослівно в розділі «In your words», нічого не переписується.
5. Ти кажеш «Build it» або що змінити.

## 2. Перша версія

- Claude збирає гру й сам її запускає, грає й робить скріншоти.
- Гра відкривається подвійним кліком по `index.html`, без встановлення.
- Усі числа, які можна підкрутити (швидкість, час раунду, кількість кущів), лежать в одному файлі `config.js`. У грі є панель повзунків на клавіші `` ` ``.
- Перша версія зберігається з позначкою (тегом), до неї завжди можна повернутись.

## 3. Цикл змін

Кожна твоя порада після гри проходить одне коло:

1. Твої слова записуються в бриф рядком «After play: …» дослівно.
2. Те, що тобі сподобалось, іде в розділ «Keep», і без питання Claude це не чіпає.
3. Те, що не подобається, іде в розділ «Avoid» (наприклад, «дощ»), і більше не повертається.
4. Claude робить зміну й перевіряє її в браузері.
5. Зміна зберігається як **iteration N**. Будь-яку iteration можна відкотити.
6. Нова версія автоматично йде на GitHub і itch.io.

Наш домовлений режим: **«Продовжуй без зупинок»**. Коли ти погодила план, Claude не питає «прийняти?» на кожному кроці, а сам зберігає й публікує. Зупиняється лише там, де потрібна ти: реєстрація, вхід, перевірка на телефоні.

## 4. План розробки (roadmap)

Для великих етапів Claude пише план у `design/roadmap.md`, ти його погоджуєш або правиш. Наш план для Rooftop мав 11 етапів: Blender-моделі → героїня → анімації → єнот → предмети → графіка → онлайн → телефон → звук → баланс → публікація. Шаблон лежить у `templates/roadmap.md`.

## 5. Оркестрація (кілька агентів одночасно)

Коли задач багато й вони незалежні, кажи **«перемикайся на режим оркестрації»**. Тоді:
- Claude роздає задачі кільком агентам; кожен працює у **своїй копії** гри й не заважає іншим;
- з Blender працює лише **один** агент, бо програма одна;
- коли агенти закінчують, Claude зводить їхню роботу докупи, перевіряє й публікує одним оновленням;
- якщо злиття складне (багато конфліктів), Claude віддає його окремому агенту з повною перевіркою.

Перед кожною задачею Claude пише одним рядком режим роботи: A — сам, B — кілька помічників, C — оркестрація, D — спершу відфільтрувати дані.

## 6. Перевірка

- Кожну зміну Claude запускає в браузері й дивиться на скріншот, а не лише читає код.
- Для балансу є автоматичні матчі ботів проти ботів (`?manual=1&sim=40`): вони рахують, скільки хованок ловлять за раунд.
- Чого Claude перевірити не може, він каже прямо: звук (у тестовому браузері його немає), справжній телефон, гра з різних комп'ютерів.

## 7. Публікація

- **GitHub** (приватно) — резервна копія кожної версії.
- **itch.io** — гра для гравців, у браузері. Сторінка спершу в режимі Draft (бачиш лише ти), потім Restricted (за посиланням) чи Public.
- **Render** — хмарний сервер для онлайн-гри; друзі приєднуються за кодом кімнати з 4 літер.

## 8. Як Claude з тобою говорить

- Українською, просто, крок за кроком: куди натиснути і що ти побачиш.
- Без команд для терміналу: технічну частину Claude робить сам.
- Чесно про те, що не перевірено або не вийшло.
